# 01. 데이터 모델링의 이해 (이해는 Two Sun)
## 01.01 데이터 모델의 이해
### a. 데이터 모델링의 개념 및 특징
- 데이터 모델링의 개념 : 현실 세계를 단순화해서 저장하기
- 데이터 모델링의 특징 : 명단추 (이름난 단추라고 외울것)
    
    + 추상화 (Abstraction): 복잡한건 떼고 필요한 데이터와 관계만 남기고 저장 (복세편살 ST)
    + 단순화 (Simplification) : 복잡한 데이터를 이해하기 쉬운 구조로 표현하는 과정
    + 명확화 (Clarification) : 데이터의 구조와 관계를 명확하게 표현하여 오래의 여지를 없애는 과정
- 데이터 모델링이 올바르게 수행되지 않는 경우 (데이터 모델링의 중요성)
    |발생 문제|설명|
    |---|---|
    |중복성|같은 데이터가 여러 곳에 저장되어 관리가 비효율적이고 불일치가 발생할 수 있음|
    |비유연성|데이터 모델이 변화에 대응하지 못해 시스템 확장 혹은 수정이 어려움|
    |비일관성|동일한 데이터가 다르게 저장되거나 표현되어 데이터의 신뢰성이 저하됨|
### b. 데이터 모델링의 관점
+ 데이터 관점 (What) : **어떤** 데이터를 저장할 것인가! 를 중점으로 두는 관점
+ 프로세스 관점 (How) : 저장 된 데이터들을 어떻게 저장하고 어떻게 조회하고 어떻게 관리할 것인가. (데이터의 흐름등을 그림으로 표현)
+ 데이터와 프로세스의 상관 관점 (Interaction) : 데이터와 프로세스가 서로 상호 의존적이다 뭐 그런 이야기,,, (근데 아무래도 프로세스도, 데이터도 서로가 있어야 의미가 있으니까용)
### c. 데이터 모델링의 3단계
+ 데이터 모델링의 종류 : 개념점/논리적/물리적
    + 개념적 데이터 모델링 : 추상적으로 데이터를 개념적으로 설계한다. 
    + 논리적 데이터 모델링 : 논리적 단계와 속성을 설계한다.
    + 물리적 데이터 모델링 : 실제로 컴퓨터에 어떻게 저장할지 설계한다.
+ 세계
    + 개념 세계 : 개념 + 논리
    + 물리 세계 : 논리 + 물리
### d. 데이터 독립성 : 데이터 중복 제거를 통한 효율성 증진
+ 데이터 베이스 
    + 시스템 등장 배경 : 기존 파일 시스템으로 부터의 탈피
        + 파일 시스템 : 고객 주문 데이터/고객 관리 데이터 등을 따로 다른 파일로 관리하게 되면서 같은 정보가 중복되어 저장되는 문제 발생, 더 나아가 수정사항이 한쪽에만 반영될 경우 문제가 발생할 수 있음
    + 데이터 통합 관리 : 중복을 제거하고 하나의 데이터 베이스에서 관리
    + 데이터 공유 및 일관성 유지 : 같은 데이터 베이스에서 조회된 내용을 여러 프로그램에서 접근 및 관리
### e. 데이터 베이스의 3단계 구조
+ 외부 스키마 : 프로그램/사용자등이 볼 수 있는 모습. 검색/필터 적용 등과 같은... (소신발언! 케이스티 파이는 외부 스키마가 굉장히 별로다!)
+ 개념 스키마 : 중간에서 내부스키마에 저장 되어있는걸 조합해서 외부 스키마로 전환하기 위한 스키마
+ 내부 스키마 : 물리적으로 데이터를 저장하는 걸 말한다 (파일/인덱스 등등..)
