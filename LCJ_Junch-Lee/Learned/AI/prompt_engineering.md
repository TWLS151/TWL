# AI를 잘쓰는 법이 아닌, AI를 '통제하는' 개발자


### AI를 어시스턴트로서

AI 출력에 의존하지 않고, 사전에 범위와 역할을 통제할 수 있는 상태

- AI가 잘못된 결과를 냈을 때, 책임은 어디에?
- AI가 작업을 망쳤을 때, 모델 or 구조 뭐가 문제인가?
- 개발자가 통제권을 유지하려면 무엇이 필요한가?


## 요구사항 -> 설계 -> 구현까지는 AI가 잘 해낸다.

- 그러나 검증, 유지 보수는? 아직 미지수


### 기존 개발의 한계 : 단순 작업, 너무나 많은 맥락 스위칭 (코드 <-> 명세 <-> 자료)

## AI Agent : 

- 등장 배경

> 하나의 AI에게 여러 종류의 일을 시키면 잘 못한다?
> 그럼 역할을 나눠서 수행하게 하자

- Reason : 지금 무엇을 해야하는지 판단
- Act : 선택한 행동 실행
- Observe : 실행 결과 확인
- 이를 반복

## AI Agent는 만능인가? 

- 추론 과정을 거쳐, 검증 결과를 도출한다 -> 실패하지 않는다?

- Agent는 여러 단계를 자동으로 수행할 수 있지만, 실패 양상도 기존 어시스턴트와 다를 뿐 분명히 존재
  - 변경 범위가 커짐
  - 사람이 검증하기 전에 다음 단계로 넘어감
  - 실패 지점이 어디인지 알기 어려움


### 방대한 수정 범위, 수정 범위 초기화, 잘못된 연쇄 실행, 책임 위치 불명확


## 결국! 핵심은 AI를 잘 통제하는 것

-> 그러기 위해서 프롬프트를 잘 짜자


## 프롬프트 엔지니어링 

: AI에 무엇을 어떻게 지시할지 설계하는 기술 

- 모델의 응답 품질은 프롬프트의 구조, 명료성, 맥락 정보에 크게 영향을 받음


### 좋은 프롬프트의 기본 구조

1. 역할과 맥락

2. 명확하고 구체적
- 목표와 조건

3. 예시 제공
- 예상되는 응답 형식을 전달하는 예시를 포함
- 모델이 패턴을 이해하도록 유도

4. 맥락과 입력 정보 제공
- 필요한 배경이나 자료를 포함해 모델이 충분히 이해하게 함

5. 검증 기준 명시
- 모델이 

## 핵심 : 모델의 답변 범위를 제한하라

- 페르소나, 주제, 등등으로 역할, 맥락, 목적, 길이 모두 지정되는 프롬프트를 짜자


## 계획, 검증, 생성 Agent로 역할을 분리하자

### 역할 프롬프트에 반드시 포함되어야 할 요소

1. 역할 선언
- 이 모델은 무엇을 하는 존재인가 / 무엇을 하지 않는가

2. 목표 정의
- 이 역할의 산출물은 무엇인가

3. 입력 명시
- 무엇을 받아서 작업하는가 (이전 단계 산출물? 원 요구사항?)

4. 금지사항
- 절대 해서는 안되는 행동 / 역할을 침범하는 행동

5. 출력 구조
- 반드시 어떤 구조로 답해야 하는가 / 자유 서술 금지
