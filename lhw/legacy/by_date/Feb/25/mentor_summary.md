# '양치기'가 되지 마세요.

- 무작정 많이 푸는 '양치기'는 한계가 명확합니다. 양치기가 되기보다 본인 뇌의 로직 플로우를 파악해야합니다. 플로우를 파악하고 본인에게 맞는 학습법을 찾아야합니다. 다음은 그 예시입니다.
```
1. 패턴형 ( 문과 대다수 )
 - 템플릿 중심으로 학습하여 실전 적용이 빠릅니다. 하지만 그만큼 학습하지 않은 템플릿의 문제, 즉 낯선 문제를 만나면 쉽게 당황합니다.
```
> 필수 템플릿 학습 및 변형 연습

```
2. 이해형 ( 이과 대다수 )
 - 원리와 증명을 중심으로 학습합니다. 덕분에 응용력이 높지만 학습 속도가 늦어지는 경우가 많고 매번 사고를 하다보니 구현의 속도가 늦습니다.
```
> 개념 시각화, 단계별 값 추적, 시간 제한 구현 훈련

```
3. 응용형 ( 감각에 의존하는 유형 )
 - 코드 실행을 중심으로 많은 코드를 접하며 그때그때 구조를 파악합니다. 이들은 실전 감각이 우수한 경우가 많지만 구조에 대한 이해가 부족한 경우 또한 많습니다.
 ```
> 기출을 기반으로 한 TOP-DOWN 식 접근, '왜'를 이용한 역추적 방식

# 성장은 무한 순환 구조를 가집니다.
 - 진짜 실력은 선형적이지 않고 아래 구조의 무한한 순환에서 생겨납니다.
 ```
 1. 이해 (WHY)
 2. 암기 (패턴화 / 내재화)
 3. 응용 (실전 해결 / 최적화)
 4. 경험을 기반으로한 이해
 ```
 - 이 순환이 끊기면 안됩니다.

 # AI 를 멘토로 삼으세요.
 - AI는 잘못 사용하면 단순한 복사기가 되고 잘 사용하면 성장 가속기가 되기도 합니다.

 ## 추천하는 활용법
 1. 이해 지원
  - '로직을 Mermaid 차트로 그려줘' == 시각화
  - '데이터 흐름을 단계별로 보여줘' == 데이터 추적
  - 'DP 를 일상에서 볼 수 있는 비유로 설명해줘' == 개념 단순화
 2. 검증 지원
  - '내가 놓친 엣지 케이스를 찾아줘' == 사고 확장
  - '이 코드가 틀릴 수 있는 반례를 만들어줘' == 디버깅 역량 향상
  - '시간 복잡도를 정확히 분석해줘' == 최적화
 3. 최적화 지원
  - '시간 복잡도를 개선해서 리팩토링 해줘' == 최적화
  - '메모리 사용량을 개선해줘' == 최적화
  - '다른 언어로 더 깔끔하게 작성해줘' == 타 언어 비교 및 학습과 최적화

# 현장에서는 점점 주니어가 사라지고 있습니다.
 - 기존의 주니어들이 하던 일을 AI가 대체할 수 있게 되었습니다. 그와 동시에 기업들은 수습기간이 없이 즉시 전력이 될 수 있는 사람을 선호하죠.
 - 하지만 주니어가 없으면 멀지 않은 미래에 AI를 다룰 시니어가 없어질겁니다. 사람은 은퇴를 하니까요.
 - 여기서 기존과 다른 역할을 수행하는 '슈퍼 주니어'가 필요하다는 걸 알 수 있습니다. 단순한 코드 작성은 대부분의 시니어들보다 AI가 더 잘합니다. 이 사실은 구현능력은 더 이상 경쟁력이 될 수 없다는 점을 시사해요.

# not 'HOW' but 'WHY'
 - 구현은 이제 경쟁력이 될 수 없다면 우리같은 개발자들은 어떡하죠?
 ## DECISION
  - 결정해야합니다. 진부할 수 있지만 AI는 코딩을 시키는대로 '잘' 하지만 '왜' 이렇게 하는지는 알지 못해요. 맥락을 읽긴 하지만 그 맥락 밖의 큰 그림을 볼 수는 없죠. 그래서 AI는 결정을 하지 못해요.

# AI를 '사용'하는 사람이 되세요.
 - 더 이상 포트폴리오에 단순한 프로젝트 경험, 기능 구현 경험, 열심히 했습니다. 등과 같은 말들은 인상적이지 않아요. 그럼 뭘 적어야할까요?
 - 바로 Decision Log 입니다.
 ```
 1. AI를 어떻게 활용했는가.
 2. AI의 할루시네이션을 어떻게 해결했는가
 3. 어떤 의사결정을 어떤 근거로 내렸는가
 4. 프롬프트 엔지니어링을 활용한 명세의 기술적 분해가 가능한가
 ```
 - 등등 코딩 경험이 아니라 AI를 사용한 기록이나 프로젝트를 진행하며 내린 결정을 어떤 합리적인 근거로 판단하고 결정했는가 등을 작성해야합니다.
 - 예를 들어 프로젝트에서 sort 알고리즘을 사용해야했는데 하드웨어의 사양이나 주어진 메모리, 자원 또는 해당 프로젝트의 목적이 어떠해서 count, bubble, merge, select 등 여러가지 알고리즘 중 하나를 선택했다. 같이 구체적이어야 합니다.

# 생산성의 증강 (augment)
 - 그런데 여기서 한 발 더 나아가서 AI를 사용하는 개발자가 아니라 'AI로 증강된 개발자'가 되면 어떨까요? 사용과 증강은 다릅니다.
 ```
 - CI / CD 자동화
 - 테스트 자동화
 - 에러 로그 분석 자동화
 - FULL-STACK 사고 확장
 ```
 - 등을 혼자서 해내는 개발자는 어떤가요?
 > 혼자서 팀 단위의 생산성을 내는 사람이 경쟁력 있다는 말을 들을 수 있습니다.
 - 그리고 프론트엔드, 백엔드 굳이 나누지 마세요. 이를 나누기 시작하면 정말 끝도 없습니다. 완전히는 힘들더라도 최대한 경계를 허물어야합니다.

# 포트폴리오의 치트키
 - 상술했듯이 '열심히 했습니다.', 기능 구현 경험, 프로젝트 경험 설명 등은 이제 의미가 없습니다. 그럼 어떤 내용을 채워야할까요?
 - 여러가지가 있겠지만 제 추천은 다믕과 같습니다.
  1. 비용 절감 경험
   - 당연히 회사는 비용 절감을 원합니다.
  2. 자동화 설계
  3. 의사결정 기록
   - 위 Decision log 와 같은 맥락입니다.
  4. 성능 개선 수치
   - 구체적인 수치를 작성하세요.
  5. AI 협업 구조
   - AI를 활용한 방법을 작성하세요.

 1. 비즈니스 도메인 이해
 2. 팀 커뮤니케이션 능력

# Q&A 추가 팁
1. 현장에서 잘 모르는 내용에 대한 질문이 들어왔을때 그냥 적당히 대답하지 마세요. 듣는 사람을 불쾌하게 합니다. 특히 상대방이 상사라면 더욱 더 조심하세요. 아는 것과 모르는 것을 구분해야합니다. 어차피 큰 기대를 하고 물어보지 않아요. 면접도 똑같습니다. 압박이 들어오면 그냥 모르겠다고 하세요. 어설픈 대답보다 낫습니다.
> 살아남은 신입들의 공통점을 묻는 질문이었습니다.

2. 본인의 역량에 대해서 크게 평가하지 마세요. 본인의 평가만큼 신뢰가 안가는 것도 없습니다. 신입에게 큰 기대를 하지 않습니다. 신입이 자신있어하는 분야가 있더라도 신뢰가 가지 않아요. 그런데 못한다고 말하는 분야는 어떨까요. 그냥 판단하지 말고 보여주세요. 이 업계는 탈출할때까지 배워야합니다. 배울 수 있다는 점을 잘 보여줘야해요.
 - 자격증 같은 것도 큰 의미가 없습니다. 스토리텔링에 연결할 수 있다면 좋겠지만 자격증 자체가 여러분의 능력을 증명하지는 않습니다. 
> 실력이 모자라서 직무에 지원할때 고민하다가 못한 경험이 있다는 질문이었고 이에 대해서 하신 말씀이었습니다. 고평가도 금물이고 저평가도 금물입니다. 직무에 적합한지에 대한 판단은 상대방이 하는거지 본인이 판단하고 지레 겁먹을 필요는 없다고 하셨습니다. 

3. 항상 도전하고 배우세요. 안주하지 마세요. 저도 한 직무에 익숙해지기 시작하면 계속 직무를 바꿨습니다. 삼성은 그게 가능하거든요. 지금은 LLM 에 간단하게 요청하면 바로바로 해결되는 문제들을 끌어안고 한 달 또는 세 달까지도 끙끙댔던 적이 있습니다. 그렇다고 지금 그게 아쉽지는 않아요. 정말 값진 경험이었다고 생각하고 있습니다.
