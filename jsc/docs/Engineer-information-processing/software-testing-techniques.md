# [Software Engineering] 소프트웨어 테스트 기법 정리

## 1. 테스트 실행 여부에 따른 분류

### 1) 정적 테스트 (Static Testing)
* **개념:** 프로그램을 **실행하지 않고** 명세서나 소스 코드를 분석하여 결함을 찾는 방법
* **장점:** 개발 초기 단계에서 결함을 발견할 수 있어 수정 비용을 절감할 수 있음
* **주요 기법:**
    * **워크스루 (Walkthrough):** 작성자 주도의 비공식적 검토
    * **인스펙션 (Inspection):** 중재자 주도의 공식적 검토
    * **동료 검토 (Peer Review):** 동료들이 함께 코드를 살펴보는 방식

### 2) 동적 테스트 (Dynamic Testing)
* **개념:** 프로그램을 **직접 실행하여** 입력 값에 따른 출력 결과를 확인하는 방법
* **주요 기법:**
    * **화이트박스 테스트 (White-box):** 내부 로직 및 구조를 확인 (제어 흐름, 루프 등)
    * **블랙박스 테스트 (Black-box):** 외부 기능 명세 확인 (경계값 분석, 동등 분할 등)

---

## 2. 정적 테스트 핵심 비교: 워크스루 vs 인스펙션

| 항목 | 워크스루 (Walkthrough) | 인스펙션 (Inspection) |
| :--- | :--- | :--- |
| **주도자** | **작성자 (Author)** | **중재자 (Moderator)** |
| **성격** | 비공식적, 정보 공유, 이해 증진 | 공식적, 엄격한 절차, 품질 관리 |
| **목적** | 로직 설명, 오류 발견 | 결함 발견 및 공식적 수정 보완 |
| **준비** | 사전 자료 배포가 필수는 아님 | 체크리스트 기반의 철저한 사전 준비 |

---

## 3. 정보처리기사 기출 핵심 Point
* **워크스루**는 작성자가 직접 설명하며 팀원들이 로직을 이해하고 오류를 찾는 과정이다.
* **인스펙션**은 가장 공식적이고 전문적인 정적 테스트 기법이며, 절차가 매우 엄격하다.
* 워크스루와 인스펙션은 **동일한 의미가 아니다.** (절차와 주도자에서 큰 차이 발생)
