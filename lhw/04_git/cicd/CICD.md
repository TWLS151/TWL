# 1. Continuous Integration
## 지속적인 통합

---

> 버그 수정이나 새 기능들이 메인 `repo` 에 자동으로 `build` 되고 `merge` 되는 방식

**주요 개념**
---
1. 코드 변경사항의 주기적이고 빈번한 머지
2. 통합을 위한 단계 ( build, test, merge )의 자동화

  
### 장점

---

1. 빌드와 테스트가 자동화가 되어 코드 작성에 더 집중할 수 있다.
2. 자동화를 통해 수시로 머지가 가능하며 이를 통해 충돌이 미연에 방지되고 워크플로우의 유지보수가 용이해진다.
3. 테스트가 통과해야하기 때문에 개발자가 개별적 검증을 거친 뒤에 메인 브랜치에 병합할 수 있어 코드의 퀄리티가 향상된다.

# 2. Continuius Delivery | Continuous Deployment
## 지속적 제공 | 지속적 배포

---

> CI를 통해 머지된 변경사항을 추가적인 검증 후 배포하는 것을 Delivery, 추가 검증 없이 CI와 배포를 연결하는 것을 Deployment 라고 한다.
